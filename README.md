# 微信 → 本机 Codex

在微信中发送文字、图片或语音，由 Windows 电脑上的 Codex 执行，再将结果发回微信。默认工作目录为 `D:\code`，使用 `workspace-write` 沙箱。支持多个微信账号，各账号的会话、登录凭据和回复独立保存；任务共用一个执行队列。

微信任务通过 Codex App Server 创建，并自动归入侧栏的「微信 Bot」分组。这个任务在桌面打开后，微信消息会通过桌面执行进程续聊。侧栏分类不隔离磁盘文件，所有账号仍使用配置的工作目录。

## 首次使用

需要 Node.js 20 或更高版本，以及已完成登录的 Codex CLI。

在本项目目录运行：

```powershell
cd D:\code\wechat-codex-bridge
npm install
Copy-Item config.example.json config.json
```

编辑 `config.json`，将 `workingDirectory` 改为自己的项目目录。`codexExecutable` 默认为 `auto`，会从当前 Windows 用户安装的 Codex 桌面程序中查找可用版本；使用其他安装方式时，可填写实际的 `codex.exe` 绝对路径。再运行：

```powershell
npm run build
npm run doctor
npm run login
```

按登录提示用微信扫描二维码、确认绑定，然后运行：

```powershell
.\start.cmd
```

电脑需保持联网、运行且不休眠；不需要额外购买服务器。这些脚本不会设置开机自启。

## 日常管理

| 命令 | 功能 |
| --- | --- |
| `start.cmd` | 在后台启动，已运行时直接显示状态 |
| `status.cmd` | 查看进程状态及最近心跳 |
| `stop.cmd` | 请求正常停止，等待最多 15 秒，不强制结束进程 |
| `add-account.cmd` | 打开新增账号扫码页面，保留已有绑定 |
| `accounts.cmd` | 查看已绑定账号的名称和本机编号，不显示登录凭据 |

从其他目录调用时，使用命令文件的完整路径。后台日志位于 `.runtime\bridge.stdout.log` 和 `.runtime\bridge.stderr.log`。重新启动前会将已有非空日志归档到 `.runtime\logs`，保留此前的故障信息。

`start.cmd` 通过 Windows 管理接口独立启动后台进程，并检查它已脱离启动方的进程组。关闭发起启动的终端或 Codex 应用，不会因此连带结束桥接进程。启动失败会明确报错；不会退回可能随启动方退出的启动方式。

桥接独立运行不等于正在执行的桌面任务也能脱离桌面：如果任务正在通过桌面 Codex 执行，关闭桌面仍可能中断该任务。桥接会保留已接收的消息和结果，不会自动重跑执行状态不确定的任务。

Codex 更新删除旧版本目录时，桥接会在启动或下一次执行任务前重新查找可用程序。其他自定义路径出错时会明确提示，不会改用未知程序。此机制不负责重启已经退出的桥接进程；进程停止后仍可用 `start.cmd` 启动。

## 让其他人使用

1. 在这台电脑双击 `add-account.cmd`，浏览器会打开本地二维码页面。
2. 把本次新增账号的二维码给对方，由对方用自己的微信扫码确认。对方无需安装 Codex。
3. 页面显示绑定成功后，对方可从自己微信里的 ClawBot 对话发送任务。已有账号继续运行，新账号约 2 秒内自动接入。

每次新增一个账号使用一次新的扫码流程。二维码过期后页面自动更新；若本次流程结束，再运行 `add-account.cmd`。关闭扫码页面不影响主桥接；尚未完成的扫码进程会自行超时。需要自定义账号显示名时，在终端运行 `npm run login -- "账号名称"`，然后打开 `.runtime\login.html`。

扫码日志为 `.runtime\login.stdout.log` / `login.stderr.log`。微信要求额外配对码时，页面会显示本机文件位置，将手机显示的数字写入该文件。

旧版单账号凭据首次启动时自动迁移到 `.runtime\weixin-accounts.json`，旧文件保留。重复绑定同一 Bot 只刷新该账号凭据；同一个微信用户换成不同 Bot 时会拒绝自动替换，避免覆盖既有路由。

旧版命令行任务会用 Codex 的历史分支接口接入可见任务，保留已完成的历史及原始任务，在状态中记录旧任务 ID；迁移日志确保重启不重复复制。后续 `/new` 直接创建可见任务。

## 微信指令

直接发送文字即可开始或继续同一个微信用户的对话。

| 指令 | 功能 |
| --- | --- |
| `/help` | 查看帮助 |
| `/new` | 开始新的 Codex 会话 |
| `/status` | 查看当前任务状态 |
| `/result` | 再次获取最近任务结果和生成的图片（例如微信回复发送失败后） |
| `/stop` | 停止当前任务 |
| `/whoami` | 查看微信通道中的用户 ID |

例如：`查看 D:\code\my-project 的登录流程是怎么实现的`。涉及具体项目时，在消息中写出项目名称或完整路径。

## 可选白名单

`config.json` 中保留用户白名单功能，默认 `accessControl.enabled` 为 `false`：当前所有能向该 Bot 发消息的人都可以触发本机 Codex。

需要限制访问时，先通过 `/whoami` 获取用户 ID，再将该配置改为：

```json
{
  "accessControl": {
    "enabled": true,
    "allowedUserIds": ["你的微信用户 ID"]
  }
}
```

只修改完整配置中的对应字段，保留其他配置。更改后运行 `stop.cmd`、`start.cmd` 重启生效。

登录资料和运行状态保存在本机。不要分享登录令牌、二维码或含登录资料的文件。

## 接入说明

微信通道基于 [腾讯公开协议](https://github.com/Tencent/openclaw-weixin/blob/main/docs/protocol.md) 实现，Codex 通过 [官方 App Server](https://learn.chatgpt.com/docs/app-server) 调用。没有安装 OpenClaw。

桥接按用户保存独立会话，所有任务串行执行。重复消息不会重复创建任务；意外退出时，不自动重跑已开始的任务。回复发送结果不确定时不会自动重发，可用 `/result` 主动再次获取结果。

如果桌面端持有该任务，桥接会使用当前安装版 Codex 的本地 IPC 续接同一个任务，按具体执行轮次 ID 读取结果和停止任务。每次微信续聊显式应用桥接的工作区沙箱、网络设置和审批策略，清除桌面上一次选择的权限 profile，同时保留模型等对话设置；仍检查实际工作目录及运行时可写目录，防止任务进入其他工作区。原任务正在桌面执行时会提示稍后重试。提交结果不确定时不会自动重发，应先在 Codex 查看原任务。该 IPC 适配已按 Windows Codex 26.908.4834.0 验证，应用升级后可能需要更新适配。

新任务会通过桌面自带的 App Tools 分组接口加入“微信 Bot”，同时保留 App Server 分组信息。分组操作后重新读取侧栏确认成员，避免只更新后台而桌面未显示。桌面不可用时记录分组失败并继续处理微信任务；下次启动或继续该任务时再次检查分组。

各账号单独长轮询收消息、发送回复；一个账号登录失效不影响其他账号。全局只有一个 Codex 执行队列，`/stop` 仅作用于同一账号下的当前用户。日志记录消息时间距本机接收的差值（含时钟差）、回复排队时长和发送接口耗时，不记录消息正文或登录凭据。

运行数据（含登录凭据、待办指令、最近结果）在 `.runtime`，已加入 `.gitignore`。Codex 继承本机模型和账号配置，显式使用配置的工作区沙箱。

微信输入支持文字、图片和普通微信语音：

- 图片下载解密后以 Codex 原生图片输入提交，支持 PNG/JPEG/WebP/GIF。可以直接发图，也可以继续发文字追问；单条消息最多 4 张，每张最多 20 MiB。
- 微信可能先投递文字、后投递图片。桥接收到图文后留出固定 2 秒合并窗口，同一账号、同一发送者在窗口内连续发来的图片和文字合成一次提问，只确认一次；合并后仍最多 4 张图片。超过窗口或任务已经开始时，消息作为后续提问；纯文字任务保持独立，命令立即处理。
- 语音优先使用微信提供的转写；没有转写时，下载原语音并在本机用 SenseVoice 识别，再作为提问交给 Codex。支持普通微信 SILK 和 PCM/float WAV，单条消息最多 4 段，每段最多 5 分钟、20 MiB。识别不需要 API Key；不能据此分析语气、声纹或背景音乐。
- 图片和语音按账号、任务分别保存到 `.runtime/incoming`。附件处理在任务队列内执行，收消息与回执不会等待识别；`/stop` 可以停止下载或识别。任何附件处理失败时，整项任务返回错误，避免只执行部分提问。
- 视频、文件输入和其他音频编码暂未接入。

本机语音模型保存在 `.runtime/speech`（约 229 MB），通过 `sherpa-onnx-node` 在 CPU 运行。新电脑执行 `npm ci` 后运行 `python scripts/setup-speech.py` 下载并校验固定模型，Python 仅用于安装，不参与日常识别。模型和个人运行数据不包含在仓库中。

Codex 本轮生成的图片会随文字回复发送到原聊天，并保存在 `.runtime/media`，每轮最多 4 张、每张最多 20 MiB。桥接只读取该轮明确的图片生成结果，不会根据回复中的文件路径自动上传其他文件。图片发送未确认时保留原图并提示，可用 `/result` 主动再次获取。
